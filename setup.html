Set up SeanBot

What happens after you invite it, in the order it happens. Seven short steps, and none of them are required to get started.

Not invited yet? Add SeanBot to your server, then come back to this page.

  1. A message arrives

    Adding SeanBot sends a short direct message to whoever invited it, offering three things: Set up SeanBot, Quick tour, and Open dashboard. Set up SeanBot asks one question - what kind of server is this - and turns on the features that fit. If that account has direct messages closed, the same menu is posted in the first channel the bot can write in.

  2. Nothing has to be switched on

    Every optional feature is already available the moment the bot joins. Setup is about switching off what this server does not want, and a choice you make is remembered from then on.

  3. Give the bot room to act

    In Discord, open Server Settings > Roles and drag the SeanBot role above every role it has to assign, remove, quarantine, mute, or manage. Discord only lets a bot touch roles below its own, so while it sits underneath them those actions quietly do nothing.

  4. Open the dashboard

    Sign in with Discord, choose the server, and open Module Settings - that is the whole list of switches, and a server that has never saved a choice sees the getting-started card that says so. /dashboard takes you to the same place from Discord.

  5. Turn logging on first

    Enable Logging in Module Settings, then open Log Config and choose All logs in one channel to begin with. That is how you see what the bot is doing rather than guessing from the outside. Separate channels are there when moderation, security, member and voice logs need to be kept apart.

  6. Add security once you can watch it

    Anti-Raid has a Canary Mode that logs what it would have caught without acting on it. Run it that way for a few days, look at what it flags on your own traffic, then let it act.

  7. Check that it is healthy

    Setup finishes with an access check naming anything genuinely wrong - a channel the bot cannot post in, or a role sitting below the member roles. Run /permissions for the same audit whenever you like, and /staff diagnose to see what is configured and what still needs attention.

If a command does not appear

It is nearly always one of three things: its module is switched off, the command is disallowed under Server Settings > Integrations, or the person typing it does not have the role.

That is the whole on-ramp. Everything past it is optional, and every module has a page of its own written for whoever ends up doing the configuring.
