Set up SeanBot

Seven steps, in the order they come at you. Follow them and you are done in about five minutes - and none of them are required before you start using the bot.

Not invited yet? Add SeanBot to your server first, then come back here.

  1. Expect a DM from SeanBot

    The moment it joins, whoever invited it gets a direct message with three buttons: Set up SeanBot, Quick tour, and Open dashboard. Press Set up SeanBot and answer the one question it asks - what kind of server is this - and it switches on the features that fit. If that account has DMs closed, the same menu is posted in the first channel the bot can write in.

  2. Then turn things off

    There is nothing to enable first: every optional feature works the second the bot joins. So go through the switches and turn off what this server does not want. Whatever you choose is remembered from then on.

  3. Now put the bot role on top

    Open Server Settings > Roles and drag the SeanBot role above every role it has to assign, remove, quarantine, mute, or manage. Discord only lets a bot touch roles below its own, so while it sits underneath them those actions quietly do nothing.

  4. Go to the dashboard

    Sign in with Discord, choose the server, and open Module Settings - that is the whole list of switches, and a server that has never saved a choice sees the getting-started card that says so. Type /dashboard in Discord to land in the same place.

  5. Set logging up before anything else

    Logging is already on, so open Log Config and pick where it goes: start with All logs in one channel. That is how you watch what the bot is doing instead of guessing from the outside. Split into separate channels later, when moderation, security, member and voice logs need to be kept apart.

  6. Tune security once you can watch it

    Anti-Raid is on from the start, so put it in Canary Mode first: it logs what it would have caught without acting on it. Let it run a few days, look at what it flags on your own traffic, then let it act.

  7. Finish with the check

    Setup ends with an access check that names anything genuinely wrong: a channel the bot cannot post in, a role sitting below the member roles. Run /permissions for the same audit whenever you like, and /staff diagnose to see what is set and what still needs you.

If a command does not appear

Check three things, in this order: the module is switched off, the command is disallowed under Server Settings > Integrations, or whoever typed it does not have the role.

That is it, you are set up. Everything past this point is optional, and every module has a page of its own written for whoever ends up doing the configuring.
